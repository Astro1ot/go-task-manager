# Junior Go Developer: 20 вопросов с краткими ответами

## Go

1. **Что такое горутина и как её запустить?**

   Это конкурентно выполняемая функция: `go work()`. Планировщик Go распределяет горутины по потокам ОС. Конкурентность не гарантирует одновременное выполнение на разных ядрах. [Effective Go](https://go.dev/doc/effective_go#goroutines).

2. **Чем отличаются каналы с буфером и без него?**

   Канал передаёт типизированные значения между горутинами. Без буфера отправитель ждёт получателя. С буфером отправка блокируется, когда буфер заполнен; чтение открытого пустого канала тоже блокируется. [Effective Go](https://go.dev/doc/effective_go#channels).

3. **Что происходит после закрытия канала?**

   Оставшиеся значения можно прочитать. Затем чтение возвращает нулевое значение и `ok == false`. Отправка в закрытый канал вызывает панику; закрывает канал обычно отправитель. [Спецификация Go](https://go.dev/ref/spec#Close).

4. **Для чего нужен `select`?**

   Он выбирает готовую операцию над каналом. Если готовы несколько, выбирается одна псевдослучайно. Если ни одна не готова, `select` ждёт либо выполняет `default`, если тот указан. [Спецификация Go](https://go.dev/ref/spec#Select_statements).

5. **Как работает `defer`?**

   Откладывает вызов до выхода из функции. Вызовы выполняются в обратном порядке; аргументы вычисляются сразу. В проекте так освобождаются ресурсы через `rows.Close()` и `cancel()`. [Effective Go](https://go.dev/doc/effective_go#defer).

6. **Что такое интерфейс?**

   Интерфейс для значений описывает набор методов. Тип реализует его неявно, если имеет нужные методы. Это позволяет менять реализации; например, функция может принимать `io.Reader`. [Effective Go](https://go.dev/doc/effective_go#interfaces_and_types).

7. **Почему интерфейс с nil-указателем может быть не равен `nil`?**

   Интерфейс хранит динамический тип и значение. Если внутри типизированный nil-указатель, тип присутствует и интерфейс не равен `nil`. [Спецификация Go](https://go.dev/ref/spec#Comparison_operators).

8. **Зачем нужны указатели и как они передаются в функцию?**

   `&x` получает адрес, `*p` обращается к значению. Указатель позволяет изменить исходный объект. Аргументы в Go передаются по значению: для указателя копируется адрес. [Спецификация Go](https://go.dev/ref/spec#Calls).

## SQL

9. **Чем отличаются `INNER JOIN` и `LEFT JOIN`?**

   `INNER JOIN` возвращает совпавшие пары строк. `LEFT JOIN` также сохраняет строки слева без совпадения, заполняя поля справа значениями `NULL`. [PostgreSQL: JOIN](https://www.postgresql.org/docs/15/tutorial-join.html).

10. **Что такое индекс и какова его цена?**

    Индекс помогает быстрее находить строки. Он занимает место и требует обновления при изменениях данных. Выгода зависит от запроса и распределения значений; для маленькой таблицы последовательное чтение может быть быстрее. [PostgreSQL: индексы](https://www.postgresql.org/docs/15/indexes-intro.html).

11. **Что такое транзакция?**

    Группа операций с общим результатом: `COMMIT` фиксирует изменения, `ROLLBACK` отменяет. Например, списание и зачисление при переводе денег должны выполняться одной транзакцией. [PostgreSQL: транзакции](https://www.postgresql.org/docs/15/tutorial-transactions.html).

12. **Что означает ACID?**

    Atomicity — все изменения или ни одного; Consistency — сохранение ограничений данных; Isolation — правила взаимодействия параллельных транзакций; Durability — сохранность подтверждённых изменений. [PostgreSQL: транзакции](https://www.postgresql.org/docs/15/tutorial-transactions.html), [изоляция](https://www.postgresql.org/docs/15/transaction-iso.html).

13. **Какой уровень изоляции PostgreSQL использует по умолчанию?**

    `Read Committed`: каждый запрос видит данные, зафиксированные до его начала. Поэтому два SELECT внутри одной транзакции могут увидеть разные результаты после чужого COMMIT. [PostgreSQL: изоляция транзакций](https://www.postgresql.org/docs/15/transaction-iso.html).

## Docker

14. **Чем образ отличается от контейнера?**

    Образ — шаблон с файлами и настройками. Контейнер — его экземпляр с собственным состоянием и записываемым слоем. Из одного образа можно создать несколько контейнеров. [Docker: образы](https://docs.docker.com/get-started/docker-concepts/the-basics/what-is-an-image/).

15. **Зачем нужен Docker Compose?**

    Он описывает сервисы, сети и тома в YAML и управляет ими командами `docker compose up` и `down`. В проекте Compose настраивает и запускает PostgreSQL. [Docker Compose](https://docs.docker.com/get-started/docker-concepts/the-basics/what-is-docker-compose/).

16. **Зачем PostgreSQL нужен volume?**

    Том хранит файлы базы независимо от жизненного цикла контейнера. Удаление контейнера сохраняет именованный том; удаление самого тома уничтожает находящиеся в нём данные. [Docker: volumes](https://docs.docker.com/engine/storage/volumes/).

## REST API

17. **Как выбирают HTTP-метод для операции с ресурсом?**

    GET получает представление, POST обычно создаёт ресурс или запускает обработку, DELETE удаляет. В проекте это GET/POST `/tasks` и DELETE `/tasks/:id`. [RFC 9110: методы](https://www.rfc-editor.org/rfc/rfc9110.html#name-method-definitions).

18. **Чем отличаются PUT и PATCH?**

    PUT задаёт полное желаемое состояние ресурса по известному URI. PATCH описывает частичные изменения. PUT идемпотентен; идемпотентность PATCH зависит от операции. Эти маршруты в проекте пока не реализованы. [RFC 9110: PUT](https://www.rfc-editor.org/rfc/rfc9110.html#name-put), [RFC 5789: PATCH](https://www.rfc-editor.org/rfc/rfc5789.html#section-2).

19. **Какие коды ответов важно знать?**

    `200` — успех, `201` — создано, `204` — успех без тела, `400` — ошибка запроса, `401` — нужна аутентификация, `403` — доступ запрещён, `404` — не найдено, `409` — конфликт состояния, `500` — внутренняя ошибка. [RFC 9110: коды](https://www.rfc-editor.org/rfc/rfc9110.html#name-status-codes).

20. **Что такое идемпотентность?**

    Повтор одинакового запроса имеет тот же предполагаемый эффект на сервере, что и один запрос. GET, PUT, DELETE идемпотентны; POST обычно нет. Первый DELETE может вернуть `204`, следующий — `404`: конечное состояние одинаково. [RFC 9110: идемпотентность](https://www.rfc-editor.org/rfc/rfc9110.html#name-idempotent-methods).
